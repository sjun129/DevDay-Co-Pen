# Claim check

대상 텍스트를 읽고 아래 세 종류를 찾아 표로 보고한다. 근거는 `docs/PROJECT_CONTEXT.md` 5장(표현 가이드)과 `reports/AI 협업 에디터 신뢰성 설계.md`.

## 1. 금지 표현 → 대체 표현

| 찾을 것 | 대체 |
|---|---|
| 준수, 인증, 고위험 요건 충족, 법적 의무 이행 | 대비 설계, 참고·정렬, 자체 평가 |
| 최초, 세계 최초, 유일한 | "2026년 9월 기준 공개 문서에서 찾지 못함" 또는 구체적 차이 서술 |
| AI 팀원 | 책임이 기록되고 되돌릴 수 있는 참여자 |
| 인젝션을 막았다, 안전하다 | 구조적으로 불가능하게 만든 것 + 정적 ASR + 적응형 ASR |
| AI 작성 탐지, 워터마크 | 탐지가 아니라 과정 기록 |
| 제안 수락·거절이 차별점 | 변경 추적은 표준. 차별점은 역할·출처·검증 상태·동시 편집 보장 |
| 신뢰 점수 하나 | 표본 크기·신뢰구간·한계를 함께 보여주는 지표 |

## 2. 미확인 사실 (원문 확인 전에는 쓰지 않거나 "미확인·보도 기준" 표기)

- 동아대학교 생성형 AI 과제 가이드라인 (공개 웹에서 찾지 못함, 동서대 규정과 혼동 사례)
- 교육부 「대학 AI 활용 윤리 가이드라인」 최종본 (초안 2026-02-27만 확인)
- 인공지능기본법 과태료 금액, 시행령 예외 조항, 고영향 "학생 평가"의 대학 포함 여부
- EU 디지털 옴니버스의 제50조(2) 유예 문구
- Liveblocks 다중 에이전트 쇼케이스, Word Copilot 변경 추적의 작성자 표시 방식
- DevDay 제출 마감일과 라이브 데모 가능 여부

## 3. 수치 인용

- 수치마다 출처가 보고서에 있는지 확인한다. 없으면 표시한다.
- 연구 수치를 Co-Pen의 효과처럼 쓰지 않았는지 본다("연구에 따르면 …이므로 이렇게 설계했다"는 가능, "Co-Pen은 오류를 53% 줄인다"는 측정 전이면 불가).
- 팀이 정한 목표치(보존률 100% 등)는 "팀 기준"이라고 적었는지 본다.

## 출력 형식

| 위치 | 원문 | 문제 유형(과장/미확인/수치) | 대체 문구 |
|---|---|---|---|

문제가 없으면 "발견 없음"과 함께 확인한 범위를 적는다.
